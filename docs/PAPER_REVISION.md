## 2. Abstract (draft)
> Zombie and shadow APIs, endpoints that remain reachable after being retired or were never inventoried, fall under OWASP API9:2023 Improper Inventory Management. We present ZombieShield, a platform that reconciles OpenAPI/Swagger specifications, source code across five web frameworks together with its Git history, and gateway access logs into one canonical inventory. Mining Git history lets ZombieShield separate *zombie* endpoints (retired from code or specification, or superseded by a newer version, yet still receiving traffic) from *shadow* endpoints (in use but never documented or implemented in scanned code). Dependency manifests are matched against OSV.dev advisories with ecosystem-aware version ranges and enriched with CISA KEV and FIRST EPSS. Three models trained on public data provide context: a payload-attack classifier (HTTP CSIC 2010 and HttpParamsDataset), endpoint models trained on 84,471 operations from 682 public API providers, and an Isolation-Forest traffic anomaly detector. On the Sock Shop microservice reference application, **[validation result: precision/recall/F1 for zombie-or-shadow detection against an independently written ground truth]**. ZombieShield works only from collected evidence and issues recommendations, not automatic changes.

## 3. New definitions (replace Sec. III / V-C text)
| State | Definition used by the classifier (`backend/app/services/lifecycle.py`) |
|---|---|
| ZOMBIE | Previously in source code or specification (Git history) **or** superseded by a newer supported version, and receiving traffic within the activity window |
| SHADOW | Receiving traffic but never present in any scanned specification or source code, current or historical |
| DEPRECATED | Marked `deprecated: true` in the specification or by the owner |
| DECOMMISSIONED | Retired and no traffic within the activity window |
| ACTIVE | In the current specification or code |

Two design points worth a paragraph each:
* **404 probes are excluded from the inventory.** Only responses that prove a route exists (2xx/3xx, 400, 401, 403, 405, 409, 410, 415, 422, 429, 5xx) create records. Otherwise a directory scan would fill the inventory with fake shadow APIs.
* **Version is taken from the path** (`/v1/...`), not from `info.version`, so specification, code and log evidence for the same operation share one canonical key. v1 split them, which caused merge failures.

Selection rule: highest mean PR-AUC across both test sets, fixed before evaluation. Cross-dataset generalisation (trained on CSIC only, tested on HttpParams): P 0.997, R 0.796, F1 0.885. Attack-type F1 on HttpParams: sqli 1.00, xss 1.00, path-traversal 0.995, cmdi 0.967.

Discussion points to include:
* **Why recall on CSIC is low.** Many CSIC "anomalous" requests contain unusual-but-harmless values. A structural pre-filter treats values made only of letters, digits and `. , @ + -` as inert, so they score 0. This removed false alarms on ordinary queries like `?size=6&page=1`, at the cost of recall on CSIC. All test rows are still counted.
* **A bug worth reporting.** An early version joined parameter values with an unusual separator character, and the model learned that character as an attack signal. Fixing it raised cross-dataset F1 from 0.55 to 0.89 and stopped false alarms on multi-parameter queries.
* Only parameter values are inspected, never parameter names or ordinary paths, so the model cannot memorise CSIC's single e-shop.

**Table C: endpoint models, evaluated on 171 providers held out of training entirely** (GroupShuffleSplit by provider)
| Task | Model | ROC-AUC | PR-AUC | Base rate | Lift |
|---|---|---|---|---|---|
| Legacy | Path vocabulary only (baseline) | 0.42 | 0.004 | 0.004 | ~1.0 |
| Legacy | **Gradient Boosting, structural features (selected)** | **0.72** | 0.013 | 0.004 | 3.4× |
| Sensitive | Logistic Regression | 0.66 | 0.258 | 0.145 | 1.8× |
| Sensitive | **Random Forest (selected)** | **0.67** | 0.259 | 0.145 | 1.8× |

Discussion points:
* **Negative result.** Path wording does not predict deprecation for unseen providers (ROC-AUC 0.42, below chance). Deprecation vocabulary is provider-specific.
* **Real-data finding.** Operations for which a newer path version exists are deprecated 32.8% of the time (38 of 116), against 1.2% overall. This supports treating "superseded by a newer version" as zombie evidence.
* Both endpoint models are weak on their own (legacy precision is under 1% at its threshold). That's why they are used as context signals shown to the analyst, not as classifiers that change a lifecycle state.

## 7. Limitations (replace Sec. VIII)
* Regex-based route extraction misses dynamically generated routes, which then appear as SHADOW when used (see Spring Data REST above).
* Only `go.mod` is scanned for Go dependencies; Sock Shop's Go services use the older glide/govendor tools, so they show no dependencies.
* Gateway logs see only traffic that crosses the gateway; internal service-to-service calls are invisible.
* The 30-day activity window can misclassify rarely used batch endpoints.
* The endpoint models are trained on public APIs, which over-represent large cloud providers.
* CSIC 2010 dates from 2010 and comes from a single application.
